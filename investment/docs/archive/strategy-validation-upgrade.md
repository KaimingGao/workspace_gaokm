# 策略验证升级重构规划（V 轨）

[← 文档索引](../README.md) · 差距依据 [§1](#1-差距结论--规划输入) · 产品边界 [design-spine · 产品边界](../design-spine.md#产品边界现行) · 已收口上一程 [upgrade-refactor-plan.md](upgrade-refactor-plan.md)（R0–R5） · Web 差距 [quant-ui-gap.md](../quant-ui-gap.md) · 数据/风控域 [data-layer.md](../data-layer.md) · [risk-layer.md](../risk-layer.md)

**规划日期**：2026-07-29  
**基线**：R0–R5 主干 + 运营/样本收尾已落地；能力地图粗估 **~70%～78%**；北极星三项已仪表化。  
**产品定位**：**策略验证**（研究台 + 模拟账户）；**暂不接实盘**。真·实盘 OMS = **N6**，仅当本规划「验证成熟闸门」通过后再另立项。  
**本文用途**：把「相对专业量化系统的路径内缺陷」落成 **可排期、可验收、可拒绝扩 scope** 的下一程升级计划；服务「验证可信 → 再谈实盘」，**不**重开 OMS / Tick / 全站 SPA。

---

## 0. 一句话目标

把系统从「研究–纸面闭环可演示、KPI 可查」升到「**策略结论可被严肃验证**」：数据不掺未来、成本与撮合足够诚实、Alpha/组合可审计加深、纸面拟合可回归——达到 **可决定是否立项 N6** 的成熟度，而不是先上实盘再补课。

```text
成功画像（本规划终点 · 策略验证成熟）
  · 观察池热门标的具备可用财务 history（非仅 demo ladder）；回测 as_of 无未来泄漏可复现
  · 回测–纸面 Corr/TE 与源审计、成本冲击在同一次验证报告中可解释
  · Alpha 面：因子字典 + 简易中性化/去冗可演示；生产分仍线性可解释
  · 组合：暴露 + 限额 + risk_parity_lite 稳态；完整 QP 仍可选、非阻塞
  · 风控：拦截 outcome 有样本与有效率趋势；无独立 OMS 式风控台亦可巡检
  · 研究：Idea→回测→纸面 ≤ 约定 TTM；Notebook 非必须，导出/CLI 路径完整
  · 闸门清单勾选后 → 才允许另开 N6 实盘立项文档
```

## 1. 差距结论 → 规划输入

### 1.1 专业栈对照（三层拆分）

| 类型 | 含义 | 本规划态度 |
|------|------|------------|
| **A. 现行边界外** | OMS / Level2 / Algo / 真强平 / 微秒延迟 | **不进 V 轨**；记入 N6 前置，不当缺陷排期 |
| **B. 路径内不足** | 财务 PIT 深度、Alpha 厚度、组合求解、撮合诚实度、研究 IDE | **V 轨主战场** |
| **C. 样本/运营债** | 空 fundamentals、未标注 outcome、真实日更薄 | **贯穿 V0 + 各阶段出门标准** |

相对专业全栈粗估见 [design-spine · 达成度](../design-spine.md#达成度评估2026-07)。一句话：

| 模块 | 粗估 | 相对专业的核心缺口（路径内） |
|------|------|------------------------------|
| 1 数据收集 | ~62% | 无 Tick/全市场仓；宏观/另类薄 |
| 2 清洗/PIT | ~62% | **真实财务时序弱**；复权策略单一 |
| 3 因子/模型 | ~62% | 因子面窄；中性化浅；NN 不上生产（刻意） |
| 4 组合/风控 | ~70% | 完整 QP / 风格·Beta / 实时 VaR 仍缺 |
| 5 回测 | ~85% | 非交易所级撮合；归因非完整 Barra |
| 6 部署 | ~55% | 纸面有、OMS 无（**有意推迟**） |

### 1.2 路径内缺陷优先级（验证可信度）

按「是否直接污染策略验证结论」排序：

| 优先级 | 缺陷 | 污染什么 | 抬高哪一柱 |
|--------|------|----------|------------|
| **P0** | 财务/源 PIT 与 live–回测不一致 | 前视偏差 → 虚假回测美 | **拟合** |
| **P1** | 成本/冲击/撮合过简 | 回测–纸面落差不可解释 | **拟合** |
| **P2** | Alpha 表达力不足 / 易过拟合调参 | 纸面夏普不可持续 | **收益质量** |
| **P3** | 组合层偏启发式 | 集中度与风险预算「看起来有」 | **收益质量 · 风控** |
| **P4** | 研究吞吐仍偏配置/脚本 | TTM 与复现成本 | **速度** |
| **P5** | 风控标注与巡检纪律弱 | 拦截有效率不可信 | **风控底线** |

**不排进 V 轨**：完整 Tick 仓、Bloomberg 密度 UI、NN → 生产 `score`、静默写生产配置、OMS。

### 1.3 需求拷问（进本规划的门禁）

任一工作包进排期须能答其一，否则砍掉或降级：

1. 是否降低 **前视 / 源不一致** 导致的虚假验证？  
2. 是否让 **回测–纸面落差** 可解释、可回归？  
3. 是否抬高 **可审计 Alpha / 组合** 的稳健性（非只调参好看）？  
4. 是否压缩 **Idea → 可复现验证** 的时间与摩擦？  
5. 是否让 **风控拦截** 可审计、有效率有样本？  

答不上来 → 不进 V 轨。若答案是「为了以后下真单更方便」而无验证收益 → 记 N6 备忘，**本轨不做**。

## 2. 锁定原则（全程）

| # | 原则 |
|---|------|
| 1 | **阶段诚实**：现行 = 策略验证；禁止暗示已接券商；N6 须过 [§11 闸门](#11-策略验证成熟闸门可立项-n6-的前置) |
| 2 | **生产 Alpha**：线性可解释 `score_bars`；NN 仅研究轨，promote 须人审 |
| 3 | **LLM 旁路**：不得改写 `score` / `stance_label`；不得静默写 `signal_config` |
| 4 | **先可信、再变厚**：PIT/成本/源审计未稳前，不并行冲完整 QP / 大规模因子库炫技 |
| 5 | **研究 / 回测 / 纸面同源**：共用 `score_bars` 与 DataService；禁止双套计分 |
| 6 | **验收可演示**：每阶段 ≥1 API/落盘 + ≥1 Web 可见 + 对应测试 / eval |
| 7 | **UI 契约**：改壳先改 [quant-ui-standard](../quant-ui-standard.md)；默认报告感 |
| 8 | **样本诚实**：demo seed / densify / synthetic_demo 须可识别；不得当「策略已验证」依据 |

## 3. 阶段总览（V0–V5）

命名 **V** = Validation Upgrade，与已收口 **R0–R5**、历史 **P\***、Web **W\*** 区分。

```text
V0  验证可信底座（真实 PIT · 源一致 · 样本纪律）
              │
              ▼
V1  成本与撮合诚实度（冲击 · 涨跌停纪律 · 落差归因）
              │
              ▼
V2  Alpha 可审计加深（因子面 · 中性化 lite · OOS 纪律）
              │
              ▼
V3  组合与风控验证稳态（暴露巡检 · outcome 纪律 · QP 可选）
              │
              ▼
V4  研究验证吞吐（导出包 · 对照实验 · TTM 真实样本）
              │
              ▼
V5  验证成熟闸门与文档收口（清单 · 回归套件 · N6 准入备忘）
              │
              ✕  现行不进入：N6 OMS（闸门通过后另文档立项）
```

| 阶段 | 主题 | 建议周期 | 主抬柱 | 依赖 | 状态 |
|------|------|----------|--------|------|------|
| **V0** | 验证可信底座 | 2～3 周 | 拟合 | R1 PIT 最小路径已有 | **主干已落地** |
| **V1** | 成本与撮合诚实度 | 2～3 周 | 拟合 | V0 源/PIT 可读 | **主干已落地** |
| **V2** | Alpha 可审计加深 | 3～4 周 | 收益质量 | V0；OOS 已有 | **主干已落地** |
| **V3** | 组合与风控稳态 | 2～3 周 | 风控 · 收益质量 | R3 暴露已有 | **主干已落地** |
| **V4** | 研究验证吞吐 | 2～3 周 | 速度 | R2 草稿/网格已有 | **主干已落地** |
| **V5** | 成熟闸门收口 | 1～2 周 | 三项可回归 | V0–V4 出门 | **主干已落地** |

**粗日历（单人）**：V0–V2 ≈ **7～10 周** 达「验证结论可信」；V3–V5 ≈ 再 **5～7 周** 达「可评 N6」。勿与 OMS / 全市场 Tick 并行。

## 4. V0 · 验证可信底座（先消灭虚假美）

**目标**：策略回测/纸面所用基本面与行情源 **可审计、可 PIT、可复现**；demo 与真实样本严格分开。

### 4.1 交付包

| ID | 项 | 落点（建议） | 验收 |
|----|----|--------------|------|
| V0.1 | **热门池真实财务 history** | `fundamentals_warmup` / 拉取写入 `history[]`；禁止把 `synthetic_demo` 当生产 PIT | 观察池覆盖率报告：`multi_point` 且非 demo 达阈值（建议 ≥70% 热门码） |
| V0.2 | **PIT 回归套件** | 扩展 `tests/test_r1_fundamentals_pit.py` + evals | 固定 as_of 用例：不得选未来点；缺史 → zero_weight |
| V0.3 | **源一致性硬化** | `data_consistency` 进日更五问与回测摘要默认展示 | 一次日更能指出 fallback / 源分裂票 |
| V0.4 | **样本纪律 UI** | 平台样本覆盖区分 seeded / densified / synthetic | 用户可见「演示样本 ≠ 验证结论」 |
| V0.5 | **空码治理** | 列出 empty fundamentals；调度补拉或显式剔除出生产宇宙 | empty 列表可导出；策略验证宇宙可配置 |

### 4.2 不做

全市场财务数仓、多源对齐中台、Tick ETL。

### 4.3 出门标准

- [x] 热门观察池真实 history 达标（非仅 ladder）— **路径已落地**（`ingest-history` / warmup 串联）；覆盖率靠运营抬升  
- [x] PIT 单测 + 1 条 eval 锁定无未来泄漏  
- [x] 样本覆盖页标明 demo vs 真实  
- [x] [data-layer.md](../data-layer.md) 更新「验证宇宙」约定

## 5. V1 · 成本与撮合诚实度

**目标**：回测「好看」与纸面「难看」之间的落差 **有结构解释**，而不是口头归因。

### 5.1 交付包

| ID | 项 | 落点（建议） | 验收 |
|----|----|--------------|------|
| V1.1 | **冲击/成本分解进验证报告** | 回测报告块：佣金 · 印花税 · 冲击 bps 分列 | 与 `cost_compare` 同源；缺模型不画假数 |
| V1.2 | **涨跌停/延后卖纪律表** | 复用 `skipped_limit*` · `exit_deferred`；Web 对照表可筛 | 至少 1 次回测能指出被纪律改写的成交 |
| V1.3 | **回测–纸面落差归因卡** | 在 Corr/TE 旁增加「可能原因」清单（成本 · 宇宙 · 调仓频率 · 数据源） | 平台/回溯各一处；规则启发式即可 |
| V1.4 | **纸面日更成本假设落盘** | `ops_report.cost_model` 与回测默认对齐可查 | 五问含成本模型版本 |
| V1.5 | **TopK 按换手计费**（续持不扣往返；印花税 5bps；滑点上限 10bps） | `costs.rebalance_cost_pct` · `topk_backtest` · topk-backtest-upgrade T0（已归档） | 单测续持/半换/全换；`cost_mode=turnover` |
| V1.6 | **TopK 可选权重**（equal / score_budget / risk_parity_lite） | `allocate_topk_weights` · Web `#quant-weight-mode` · T3（已归档） | 默认等权；报告披露 weight_mode |
| V1.7 | **CostPort 单源 + evals** | `cost_port.py` · `path_cost_port_aligned` · T4（已归档） | 纸面/回测/因子费率对齐；禁第二套隐性费率 |

### 5.2 不做

交易所撮合引擎、部分成交队列、融资融券。

### 5.3 出门标准

- [x] 同策略「回测报告 + 纸面一段」并排可读成本假设  
- [x] 至少 1 条集成测：改冲击档 → metrics 单调变化  
- [x] [quant.md](../quant.md) / 回测脚注更新方法论  
- [x] TopK 含成本按换手计费（见 topk-backtest-upgrade · T0，已归档）

## 10. 依赖与并行

```text
V0（PIT/源） ──┬──► V1（成本/撮合） ──► V5 闸门
               ├──► V2（Alpha） ─────────────┤
               └──► V3（组合/风控） ──────────┤
V4（吞吐）可与 V2/V3 后半并行 ───────────────┘
```

| 可并行 | 说明 |
|--------|------|
| V0.4 样本纪律 UI ∥ V0.1 拉取 | UI 不阻塞拉数 |

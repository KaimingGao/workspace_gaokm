# 量化研究台说明书（Web）

[← 文档索引](README.md) · **产品主轴**见 [design-spine.md](design-spine.md) · 原理见 [quant.md](quant.md) · 运维见 [quant.md · 运维](quant.md#量化运维)

**产品定位**：本 Web 是 **策略验证台**——观察名单、回测、**模拟账户**交易与 AI 命令；**现行不涉及真实账户交易**，一切买卖只记在本地纸面账本（假钱），用于策略与流程验证。待验证成熟后再评估实盘（N6）。边界见 [design-spine · 产品边界](design-spine.md#产品边界现行)。

**壳层**：侧栏六业务模块 + 顶栏「AI 助手」（⌘K）见 [quant-ui-refactor-plan.md](archive/quant-ui-refactor-plan.md)（壳层简史，已归档）。首页 `/` 重定向数据中心；**全屏对话 `/chat` 已下线**（→ `/watching`）。默认浅色，A 股红涨绿跌。升级落地进度见 **[§ 升级方案](#web-ui-全面优化升级方案)**。

图表：观察 / 仪表盘 / 模拟 / 回溯已接 **Lightweight Charts**（十字线 · MA）。回溯报告含成本假设与归因表；页内「回测怎么跑」折叠说明 lookback/horizon 日程；可跑 **参数扫描热力** 并 **导出研究包 / 回测报告**。策略页有策略卡晋升与因子字典；选股因子系数在研究枢纽。全局 **⌘⇧K** 命令面板跳转。顶栏 **告警铃**（可授权浏览器通知）。交易执行有 **产品北极星 KPI**（滚动夏普/卡玛 · 回测–纸面 Corr/TE · TTM；`GET /api/north-star`）；平台负责 **纸面日更调度**。LLM 模型在 **AI 抽屉**（⌘K）。接口失败时顶栏下有红色降级条。仪表盘净值可走 **React 岛**（CDN 失败自动回退）；观察页可 **表|图分屏**；全站 **`/ws/live` 实况** 推送纸面指标并轻量刷净值；顶栏可切 **紧凑密度**；观察/模拟主表为 **虚拟滚动**（预算 500 行；岛失败时回退分页）。

**产品聚焦三件事**（观察 ≠ 模拟）：

1. **观察** — 维护要长期看的股票名单，并从这里**建仓**进模拟；对话做解读与问答  
2. **模拟** — 已有仓位的**账本与管理**（加减仓 · 清仓 · 净值曲线）  
3. **回溯** — 对着历史交一卷  

**一条贯穿的原则**：谁决定「买什么、买多少」，就归谁。你决定的走主路径；规则决定的收进「进阶」，并在持仓上标出处。

## 用户心智与验证闭环

系统定位是 **策略验证台（假钱）**。用户常只感知到两件事——这与主路径一致，但容易**高估「验证」的严格程度**：

| 常感知目标 | 页面动作 | 真实含义 |
|------------|----------|----------|
| 不定期手动策略调仓（`short_conservative`） | 交易执行 · 策略调仓 → 预演 → 确认 | **结构层**：截面 Alpha → 持仓结构 → 持有期收益；纸面流程验证，应再对照回测、五问、风控、北极星 |
| 做 T 回测验 T 策略 | 历史回测 · 做 T 回测（落地则交易执行 · 预演/确认） | **执行 overlay**：C 相对 C_τ 破带定正/反 T（≠ 调仓 τ **买入闸**）；5m 往返价差；非独立选股 Alpha |

定义长表见 [quant.md · 策略调仓 vs 底仓做 T](quant.md#策略调仓-vs-底仓做-t)（含 **ŷ_τ 分工**）。

推荐闭环（侧栏顺序即引导顺序的一种读法）：

1. **数据中心** — 选池、看评分/倾向、人工建仓  
2. **历史回测** — rank_lots / 成本：先问「历史上这套规则是否像样」  
3. **交易执行** — 手管仓 + 策略调仓 + 可选做 T：问「纸面能否落地」  
4. **策略中心** — M prior 人审写盘（个股舆情只在数据中心徽章；选股 β 在研究枢纽）  
5. **平台** — 纸面日更调度（北极星 KPI 在交易执行）  

**易漏能力**：调仓五问与纸面日更；账户风控提示/拦截；告警→配置建议；回测参数扫描与导出研究包；AI 只解读不改分；持仓出处（手动/策略）。

产品主轴长文见 [design-spine · 用户心智与验证闭环](design-spine.md#用户心智与验证闭环现行)。

设计主轴（数据→信号→因子→倾向→动作 · 量化主轴 vs AI 旁路）见 [design-spine.md](design-spine.md)。  
**改 UI 契约**（页面唯一任务 · 组件白名单 · 验收清单 · `ASSET_V`）见 ****[§ UI 契约与标准](#web-ui-标准研究台)****。

进阶能力集中在侧栏 **研究枢纽**（`/quant`：因子 · 运维 · 日报）；`/paper` 仍有路由并重定向到 `/follow`。  
AI 只解读，**不得改写** `score` / `stance_label`。

名词见 [quant.md · 入门概念](quant.md#量化入门概念)。

## 仪表盘

路径：`/dashboard`（`/` 重定向至此）。**唯一任务**：开盘报告式态势感知——市场、纸面 KPI、风险、净值、仓位/信号，**不负责买卖**。看完再去数据中心 / 交易执行 / 策略中心动手。

设计逻辑与设计语言（改 UI 时遵守）见 [§ UI 契约 · 仪表盘](#web-ui-标准研究台)。

### 主要功能（从上往下）

1. **概览**  
   指数 / 涨跌家数 / 持仓市值 + 纸面 KPI（今日/累计收益、Sharpe、最大回撤、胜率）。  
   收益用 **A 股红涨绿跌**；Sharpe/胜率等质量指标用绿/红告警语义（非涨跌色）。

2. **风险**  
   摘要条（VaR / Sharpe / 回撤 / 集中度等）+ 年化收益/波动 / Sortino / Calmar。

3. **净值路径**  
   累计净值曲线（起点 100）；可勾选对比沪深300；区间 30D / 90D / YTD / ALL。约 90 秒自动刷新。

4. **风险分解**  
   回撤曲线 · 历史 VaR 直方图 · 持仓板块热力。

5. **仓位与信号**  
   资产配置（横向条带）· 板块暴露 · 最新信号 · 策略卡列表。

### 怎么看一屏（约 30 秒）

| 顺序 | 问自己 | 看哪里 |
|------|--------|--------|
| 1 | 市场与持仓广度怎样？ | 概览行情卡 |
| 2 | 账赚钱了吗？回撤/夏普是否失控？ | KPI + 风险 |
| 3 | 净值最近在爬还是在掉？ | 净值路径 |
| 4 | 尾部风险与板块结构？ | 风险分解 |
| 5 | 仓位集中在哪？有什么信号？ | 仓位与信号 |

### 边界（避免误用）

- **不能**在仪表盘下单或改名单；动作去侧栏对应模块。  
- 曲线依赖交易/日更产生的快照；空仓时曲线可能为空。  
- 约 90 秒自动刷新；也可点页头「刷新」。

## 操作流程（照着做）

```text
① 启动 → ② 观察名单放几只票 → ③ 对话解读
        → ④ 回溯看历史表现 → ⑤ 纸面初始化 → ⑥ 模拟买卖几天
```

### ① 启动

```bash
cd quantlab
python3 -m pip install -r requirements.txt
bash scripts/setup_quant.sh   # 可选：观察名单 + 纸面
python3 run_web.py
```

打开 `http://127.0.0.1:8000`。

### ② 观察：长期名单

1. 打开 **`/watching`（观察）** 或右侧「观察」Tab  
2. 搜索加入要长期看的股票；勾选后点「移除所选」删除（不影响模拟持仓）  
3. 打开列表会自动拉现价等行情，并拉近期**资讯标题**与规则**情绪徽章**（不进 score）；可点表头 **评分** / **量** 排序（再点切换升降）  
4. 点行内「详」看标题列表；打开列表会带上最近一次舆情告警标记（页内告警，无推送）  
5. 「模拟仓位」列显示这只票在假账里的状态：  
   - **未持** → 点 **建仓**，填每只买多少股，看清现价 / 花费 / 剩余现金后确认  
   - **已持 N 股** → 点一下跳到模拟页管理  
6. 要一次进多只，勾选后点表下 **加入纸面**：默认按金额（可切仓位% / 股数），清单里可按只改；确认前仍先看合计花费与剩余现金；标注零成本假设  
7. 确认后，表下 **建仓记录** 按日分组展示（名称 · 股数 · 价 · 金额），与模拟页交易记录同构；无历史流水时用当前持仓兜底

建仓一律按现价假买、不打分，成交后在模拟页持仓标为 **手动**。  
舆情细节见 [architecture.md · 舆情层](component/risk.md#舆情与另类数据sentiment--alt-data)。

### ③ 对话：解读与问答

- 「茅台现价」→ 行情解读  
- 「分析 ×× 能不能买」→ 深度分析  
- 右侧可对照观察名单与回复 Tab  

### ④ 回溯：历史回测

打开 **`/replay`**，对观察名单跑 rank_lots 历史回测。工具栏可勾选观察池分档（A 强 / B 中 / C 弱）收缩**调仓**宇宙，便于 A vs A+B vs 全档对照；勾选同步到 live 调仓闸。**做 T 回测不看分档**（宇宙=纸面底仓，选腿不吃 ŷ_oo）。  
**不必**先有纸面账户。调仓 KPI：**胜率**＝日净值&gt;0，**命中率**＝成交 `sign(ranking)=sign(realized_ranking)`（真实=(open[T+1]−price(τ))/open[T]；最后一个交易日无真实值不计）。净值图下有分票贡献表（盯市盈亏 / 本金）。跳过原因写在成交账动作列，可下 CSV。调仓/做 T 跑回测时标题行显示「回测中…」，闲时不占位。

### ⑤⑥ 纸面 + 模拟：假钱买卖

1. 打开 **`/paper`** 初始化假账（若 `setup_quant` 已做过可跳过）  
2. **`/follow` 模拟** 分三层，按使用频率与「谁做决定」排布：

| 层 | 位置 | 放什么 |
|----|------|--------|
| 主区 | 页面正文 | 净值 · 持仓 · **操作区**（策略调仓预演/落账 · 交易记录）；注资 / 减资 / 回零在概览「调资」卡 |
| 按需 | 折叠区 | 做 T（Worker · 预演→确认；规则在历史回测改） |

- 本页**不开仓**：新仓只从观察页建仓进来；空持仓时有「去观察建仓」入口  
- 观察页点「已持」会跳到本页并**高亮 / 选中对应持仓行**；清仓 / 加减仓后观察列状态会回写  
- 持仓表上方「出处对照」默认折叠为一行摘要；行内「出处」列同义  
- 表头可按 **市值 / 评分** 排序；点行看单票收盘价曲线，评分列可点看明细  
- 「手动预演」仅在启动时间～10:00 出报告，点**确认落账**才现价成交；过点不补跑、不挂开盘单（启动时间在交易执行页独立配置，不跟回测钟）
- 自动调仓栏：启动时间旁有一条 **w_oo ↔ w_τc** 配重滑条（互补）；改钟时建议 ≤09:30 → 0.9/0.1、>09:30 → 0.1/0.9，也可手调后落盘
- 成交成本模型在页顶常显；注资 / 减资 / 回零在概览「调资」卡

`/paper` 是模拟账户的**初始化 / 高级配置**页（不进主导航），日常买卖请用 `/follow` 模拟。

涨跌归因与「不强因子」边界见 [quant.md · 入门概念](quant.md#量化入门概念)。

## 四页主表布局规范

观察 · 模拟 · 策略 · 回溯的主表须保持一致（完整契约见 [quant-ui-standard](quant-ui.md#web-ui-标准研究台)）：

| 规则 | 要求 |
|------|------|
| 同壳同宽 | 主区 `.page-main` **铺满侧栏右侧**（非 1000px 居中）；六页 + 仪表盘同壳；左右 gutter 仅 `--page-gutter-x`（默认 16px）；页体左右 `padding:0`；表与 wrap 均为 `width: 100%` |
| 无横向滚动 | 容器 `overflow-x: hidden`；禁止用列 `min-width: Nrem` 撑破表 |
| 列宽分配 | `table-layout: fixed` + 百分比列宽；数值列可省略 |
| 股票名 | **至少完整显示前 6 字**，第 7 字起才 `…`；禁止 CSS 再截一层 |
| 贴边留白 | 首列 `padding-left: 18px`，末列 `padding-right: 22px` |
| 模拟持仓 | `.follow-holdings-card` 左右不额外缩进 |

实现落在 `web/static/css/`（「四页表格」共用块）。Cursor 规则：`.cursor/rules/quantlab-table-layout.mdc` · `.cursor/rules/quantlab-web-ui.mdc`。

## 1. 六大功能模块对照

### 1.1 策略研发工作台（Quant IDE）— 弱

| 专业能力 | 本地现状 | 判断 |
|----------|----------|------|
| Monaco / 在线写策略 | **已退役**；选股权走研究枢纽 β，限额走策略卡 promote | 不再列为缺口 |
| Notebook 探索 | 无 | 缺口 |
| 数据字典 / API 插入 | 无；AI 旁路代偿一部分 | 缺口 |
| 因子 / 策略规格 | `/strategy` 只读 IC/权重 + promote | 有骨架，偏「看卡」不是「写策略」 |

**缺陷**：研究入口是「表 + 调参按钮」，不是 IDE；策略迭代依赖改配置 / 离线脚本，Web 闭环断在「写代码」。

### 1.2 回测与历史绩效 — 中等偏弱

| 专业能力 | 本地现状 | 判断 |
|----------|----------|------|
| 参数网格 / 热力图 | 产品面已下线（lookback×K 属旧 TopK 探针） | 不提供 |
| 年化 / 夏普 / 回撤 / 胜率 / 命中率 | `/replay` 五卡 + 曲线（胜率=日净值&gt;0，命中率=ranking 预估 vs 真实） | 有 |
| Brinson / 因子归因 | 简化选股超额，非完整 Brinson | **深度不够** |
| Tick / 分钟逐笔回放 | 无；日线级成交样本 | 缺口（日线产品可接受） |
| 滑点 / 手续费拆解 | 成本模型有，UI 偏摘要 | UI 不够专业报告级 |

**缺陷**：能「跑一轮看结果」，缺机构报告里的**归因矩阵、参数曲面、信号–成交对照回放**。

### 1.3 实盘 OMS / EMS — 故意缺失（边界外）

TWAP / VWAP、订单状态机、多账户矩阵、盘口下单 —— **全部不在产品范围**。本地是「加减仓确认 + 日更调仓预演」，不是执行管理系统。

**不要按 OMS 打分**；能力地图中本块接近 0 是**策略验证阶段**预期。真·实盘见 [design-spine N6](design-spine.md#北极星实现路径n1n6)（验证成熟后另立项；不计入 [产品北极星](design-spine.md#产品北极星) 分子）。

### 1.4 数据中心 — 薄

| 专业能力 | 本地现状 | 判断 |
|----------|----------|------|
| 多源（Tick / 财务 / 舆情…） | 日线为主 + 舆情标题；财务 PIT 仍弱 | 数据深度不足 |
| 数据质量看板 | `data_quality` / `fallback` 进五问文案 | **有信号、无独立监控页** |
| 缺失率 / 修复记录可视化 | 无 | 缺口 |

**缺陷**：`/watching` 是「观察名单工作台」，不是专业 Data Center；侧栏命名对齐了，能力未对齐。

### 1.5 风控管理 — 有规则、缺终端

| 专业能力 | 本地现状 | 判断 |
|----------|----------|------|
| 事前拦截 | 限额 / 涨跌停近似 / 黑名单类后端逻辑 | 有 |
| 事中敞口（行业 / Beta / 集中度） | 预算 lite、行业告警、五问展示 | 浅 |
| 阈值配置 UI / 强平流 | 策略限额多只读；无独立风控台 | **UI 缺位** |

**缺陷**：风控结果散落在待办 / 五问 / 调仓报告，没有 Risk/Ops「敞口仪表 + 阈值编辑 + 审计列表」专页。

### 1.6 系统监控与运维 — 运维级偏弱

| 专业能力 | 本地现状 | 判断 |
|----------|----------|------|
| 网关 / 引擎 CPU · 延迟 | 无 | 边界外 / 远期 |
| 健康 / 调度 / 告警 | daily health、schedule、出站告警 | 有 |
| 全链路合规审计 UI | DecisionRecord / feedback / promote | 有碎片，无审计工作台 |
| 断线红 Banner / 自动重连 | REST 轮询；无 WebSocket；网络降级弱 | **实时 UX 缺口** |

## 2. UI/UX 相对专业终端

按「效率至上、信息高密度、抗疲劳、低延迟」对照：

| 维度 | 专业终端 | 本地 | 结论 |
|------|----------|------|------|
| 视觉 | 暗色为主、去装饰、硬边 | 浅色默认、报告感、密度克制 | 对研究员合理；对盯盘不专业（**选型，非疏漏**） |
| 布局 | Docking / 分屏 / 布局方案 | 固定六模块单主列 | 无法一屏并列名单 + K 线 + 持仓 + 日志 |
| 密度 | 11–12px、紧凑/宽松切换 | 报告块序、刻意克制 | 与标准「不学 Bloomberg」一致 |
| 键盘 | 全局热键 + Command Palette | 主要 ⌘K（AI） | 效率上限是点按钮 |
| 图表 | 十字光标、指标、画线 | 自绘 canvas 日线 | Lightweight Charts 未落地（P2） |
| 盘口 / 逐笔 | Level2、Time & Sales、闪烁 | 无 | 边界外 |
| 表格 | AG Grid 级虚拟滚动 / 行内编辑 | 自研 `.quant-weight-table` | 大数据量与复杂交互弱 |
| 实时 | WebSocket 局部重绘、节流 | ~90s 轮询 | 研究够用，非交易终端 |
| 权限合规 UX | RBAC、脱敏、二次确认体系 | 单用户本地；调仓确认有 | 非机构权限模型 |

## 3. 前端技术栈差距

| 专业推荐 | 本地 | 后果 |
|----------|------|------|
| React + TypeScript | 多页 HTML partial + 原生 JS | 复杂状态 / 布局难做 |
| Zustand + WebSocket | `fetch` + 局部全局状态 | 难做高频局部刷新 |
| Lightweight Charts | 自绘 canvas | K 线交互天花板低 |

| Dockview / Golden Layout | 无 | 无专业分屏 |
| Web Worker | 基本无 | 重计算易卡主线程 |

[quant-ui-refactor-plan P2](archive/quant-ui-refactor-plan.md) 已写明 Monaco · Lightweight Charts · 可选 React · 实盘（边界外）——团队已知，尚未切刀。

## 2. 页面契约

每页只允许下列主区块；新增块须改本表。

### `/watching` 观察

| | 约定 |
|--|------|
| **唯一任务** | 维护名单；从这里建仓进模拟 |
| **主区必有** | 搜索加入 · 主表（行情/评分/倾向等）· 批量「加入纸面 / 移除」· **建仓记录**（流水，与模拟页交易记录同构） |
| **自动** | 名单加载后拉行情 / 评分摘要 / 情绪（不写 config） |
| **禁止** | 策略调仓确认流、净值大图、回测指标卡 |
| **忙/空** | 拉行情时 meta 提示；空名单引导搜索 |
| **决策归属** | 建仓金额/股数由**人**拍板 |

### `/follow` 模拟

| | 约定 |
|--|------|
| **唯一任务** | 管理已有仓位（**唯一**买卖/调仓/做 T **落账**入口；规则在 `/replay` 改） |
| **主区必有** | 净值摘要 · 持仓表（含情绪徽章）· 操作区（交易/资金/策略调仓预演）· 分组打分状态 · 调仓时可显「五问」ops |
| **自动** | 加载后刷持仓并显示加载状态；情绪同源 `/api/watching/sentiment`（不写 config） |
| **按需** | 持仓区「刷新」重拉账户 / 评分 / 情绪 |
| **按需折叠** | 做 T · 对比 |
| **禁止** | 开新仓（引导去观察）；把研究枢纽整页塞进来；在研究页写 paper |
| **忙/空** | 调仓/日更按钮 busy；空持仓 →「去观察建仓」 |
| **决策归属** | 手动加减仓 = 人；`mode=active` 时手动预演吃 live 组权簿；否则策略规则调仓 |

### `/replay` 历史回测

| | 约定 |
|--|------|
| **唯一任务** | 改调仓/做 T 规则并做历史验证：观察名单 rank_lots 回测 + 持仓做 T 回测 |
| **主区必有** | 调仓回测（五卡：累计 / 超额 / 回撤 / 胜率=日净值&gt;0 / 命中率=ranking 预估 vs 真实；规则表单 · 回测窗口/**模型（研究/执行）**/回测时间/**观察池分档 A·B·C** · 日收益柱 · 分票贡献 · 成交账）· 做 T 回测 |
| **禁止** | 纸面买卖/预演落账按钮、观察名单编辑 |
| **忙/空** | 调仓/做 T 进度均在各自标题行，闲时隐藏；无结果时「先跑回测」；刷新恢复上次落盘（不重跑） |

### `/strategy` 策略

| | 约定 |
|--|------|
| **唯一任务** | M prior 人审写盘；个股舆情只在数据中心徽章；选股 α 在研究枢纽 |

#### 配置写盘边界

- **选股真源**：研究枢纽 `ReturnScoreModel` / 分组 β → live promote
- **策略限额**：StrategySpec / `paper.rules`（本页不再提供空壳 promote 按钮）
- **ŷ 门槛**：观察页直方图只读 `scoring` 滞回；**不得**在策略页改 weights。y_trade / y_fuse 权重与做 T 覆盖在 `/replay`（`POST /api/paper/execution`）；`/follow` 只读规格并预演/落账

### `/quant` 研究枢纽

| | 约定 |
|--|------|
| **唯一任务** | 观察池按 OLS β 分组 → 一组一表建议权 → **人审落地**（不写全局 weights） |
| **主区必有** | **概览五卡**（观察池 · 分钟 Ready · ŷ_oo · ŷ_τ · 落地）· **观察池上限**（默认 300、最大 1000，写入 `watching.json`）· 股票分组（跑分组 · 状态条 · **跨组健康矩阵含 MSE / 开盘命中率** · **IC 时序** · 一组一表 · **拟合 A/B/C 档**）· **落地条**（mode/version/覆盖率 · **宇宙分档（保存写入 live）** · 对照/启用 · 关闭/回滚/导出/刷新簿/建议重估 · 双分样本）· 探针 · 概览 **Holdout日**（1～60，默认 20；Ridge 与 ŷ_oo 跑分组共用；启用时研究/执行组 β 一并落盘） |
| **按需折叠** | 全局对照（阈值/横截面）· 日报 |
| **禁止** | 把各组权合并进 `signal_config.weights`；跨组统一总榜冒充分组；无健康门禁直接 active；**本页写 paper / 调仓** |
| **落地两步** | ① `cluster-live/apply`（shadow）→ ② `mode=active`（门禁）；调仓经侧栏 `/follow` |
| **日更** | `mode=active` 时组 ŷ 进观察池打分；调仓走 `/follow` 观察池 `rank_lots`；映射陈旧可自动降级 |
| **决策归属** | 晋升/启用 = 研究页人审；**买卖/调仓确认 = 交易执行页**；自动 OLS 重聚类不自动 promote |

|--|------|

### `/dashboard` 仪表盘

| | 约定 |
|--|------|
| **唯一任务** | 纸面组合报告墙：市场 · KPI · 风险 · 净值 · 仓位/信号（开盘先看这一屏） |
| **主区必有** | **概览**（指数/广度 + 纸面 KPI）· **风险**（摘要条 + 收益/波动卡）· **净值路径**（累计净值 · 可选沪深300 · 区间 tab）· **风险分解**（回撤 · 历史 VaR · 板块热力）· **仓位与信号**（配置条带 · 板块暴露 · 最新信号 · 策略卡） |
| **次要** | 无强制折叠次要带；动作落在侧栏业务页 |
| **数据来源** | 前端汇聚 `/api/dashboard/*`（market-overview / kpis / risk-metrics / nav-curve / sector-heatmap / signals / allocation / factor-exposure / drawdown / var-historical） |
| **禁止** | 下单 · 改观察名单 · 嵌全屏对话 · 堆完整回测报告 |
| **刷新** | 进页拉取；约 **90s** 轻量轮询；页头「刷新」 |
| **视觉** | 收益类用 A 股红涨绿跌；**质量类**（Sharpe/Sortino/Calmar/胜率等）用 `--ok` / `--danger`；配置用**横向条带**（不用饼图）；浅色默认 |

路径：`/dashboard`（`/` **302 → `/dashboard`**）。使用说明书见 [§ 说明书 · 用户心智](#量化研究台说明书web)。

#### 设计逻辑

**唯一任务**：开盘报告式态势感知，不是聊天台，也不是交易台。  
一屏回答：「市场怎样 → 账与风险怎样 → 净值轨迹 → 仓位/信号结构」。

**信息块序**（对标聚宽/米筐报告，不借 Bloomberg）：

```text
概览（行情+KPI） → 风险摘要 → 净值路径 → 风险分解 → 仓位与信号
```

先读数字与风险，再看结构；动作落在侧栏业务页，仪表盘只做摘要。

**主次分工**：
- **主区**：上述五段报告轨  
- **未挂载（可选/另开）**：调仓五问、待办条、策略指纹、React 净值岛（`#dash-equity-react-root`）——现行报告墙不强制

**边界**：不下单、不改名单、不嵌全屏对话、不堆完整回测报告。

#### 设计语言

**块序语言**：`指标 → 曲线 → 表/条`

**组件**：复用 `.dashboard-head` / `.dashboard-section*` / `.dashboard-card` / `.dashboard-kpi-*` / `.dashboard-chart-host`；图表 Lightweight Charts + DOM 条带/直方图。

**视觉约定**：
- **主列铺满 · 同壳 gutter**：`.page-main` 吃满侧栏右侧；左右仅 `--page-gutter-x`（默认 16px）  
- **收益** → `--color-up` / `--color-down`；**质量** → `--d-quality-pos` / `--d-quality-neg`（绑 `--ok` / `--danger`）  
- 数字等宽/tabular；配置与暴露用细条权重，**不用饼图墙**  
- 字号阶梯：Micro11 / Caption12 / Body13 / Section14 / Title18 / KPI20  

**一句话**：仪表盘是「纸面组合的报告封面」——报告块序 + 收益/质量分色 + 条带结构，把决策前置信息聚到一屏。

| # | 原则 | 含义 |

**成功一句话（路径终点）**：研究员能在 Web 上完成「看数 → 跑回测看专业报告 → 建仓/调仓可审计 → 数据质量与风控一眼可查」，并能看见 **纸面风险调整收益与回测–纸面拟合**；图表与表格达到工业件水平；仍不冒充实盘终端。

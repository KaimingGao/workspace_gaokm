# 模型工厂 × 研究枢纽 — 配方验证与执行

[← 文档索引](../README.md) · 产品主轴 [design-spine.md](../design-spine.md) · UI 契约 [quant-ui.md](../quant-ui.md) · Arm·T 实现 [arm-t.md](arm-t.md) · ŷ 契约 [quant.md](../quant.md)

**定位**：模型工厂验证配方，研究枢纽执行配方。本文是这条拆分的规划真源。  
**阶段**：策略验证（研究台 + 纸面）。工厂不写研究套 / 执行套；live 变更仍须人审。

---

## 1. 配方与执行

模型工厂验证配方。研究枢纽执行配方。

配方是结构、因子包、超参和训练实现。工厂用一次 Holdout 留下 OOS 指标，并用该版本可加载的模型跑离线历史回测、留下收益。OOS 和收益一起决定这套配方值不值得执行。

执行是枢纽选定一套配方之后，例行调用这套配方的训练实现，写入研究套。历史回测默认读研究套，表单可以改选执行套做对照。执行套只由研究套人审晋级，live 只读执行套，缺失时不退回研究套。某个历史日用的是该日之前已经落在研究套里的那一版，不用今天的执行套倒打整段历史。

工厂没有研究套和执行套，也不做例行调度。工厂页面上选中哪一版，都不改变这两个槽。枢纽决定何时滚、写入哪个槽、执行套能不能换。训练代码仍在工厂：枢纽不另写一套 Arm·T 或 LightGBM 拟合。

```text
模型工厂（/yhat-l · /yhat-t · /yhat-r）  →  验证配方 · Holdout OOS · 按版本号提供可访问 / 可加载 / 可预估的模型
离线历史回测                   →  只读工厂版本，预估后跑收益；不写套槽、不改 live
数据中心（/data）              →  观察池只数 · 日线 / 分钟 / 物化
研究枢纽（/quant）             →  选定配方 · 例行写入研究套 · 人审晋级执行套
例行历史回测（/replay）        →  默认读研究套（该日之前已落地的那一版）
交易执行 / live                →  只读执行套
```

| 角色 | 负责 | 不负责 |
|--|--|--|
| **Transformer 工厂**（`/yhat-t`；旧 `/yhat-tf` 重定向） | 四头 **Arm·T** 的配方验证、Holdout OOS、按版本号提供可加载可预估的模型，供离线历史回测 | 研究套 / 执行套、例行调度、live promote、例行回测落账；**不再同页训 Arm·L** |
| **LightGBM 工厂**（`/yhat-l`） | 四头 **Arm·L** 的配方验证、OOS、按版本号提供可加载可预估的模型，供离线历史回测 | 同上；**不再同页训 Arm·T** |
| **Ridge 工厂**（`/yhat-r`） | 四头 **Arm·R** 的配方验证、OOS、按版本号提供可加载可预估的模型。回归头拟合收益，排序头拟合日内稠密名次 | 同上；不建序列面板 |
| **数据中心**（`/data`） | 观察池只数与重建对齐、日线/分钟/L1·L2 物化 | 配方验证、套槽、live promote |
| **研究枢纽**（`/quant`） | 选定配方、例行把配方拟合进研究套、研究套人审晋级执行套、跨厂对照 | 拉数、物化、观察池只数（在数据中心）；在枢纽页改超参做配方搜索 |
| **离线历史回测** | 按版本号加载工厂模型、预估、计算该版收益 | 接入历史回测页、写研究套 / 执行套、改 live |
| **例行历史回测 / 交易执行** | 读枢纽的研究套 / 执行套打分 | 直接改读工厂下拉 |

把某一版工厂权重永久钉进例行回测和 live，覆盖不了这两条链路。它们要的是会滚动的槽，槽在枢纽。工厂版本回答两件事：Holdout OOS，以及用该版本离线跑出的历史回测收益。

### 0. 页面拆分（A0，版本管理之前）

改造前必须先拆掉 Scheme LT「同页双臂」：

| | `/yhat-l` · Arm·L | `/yhat-t` · Arm·T |
|--|--|--|
| 模型 | LightGBM / LambdaRank | `SeqFactorTransformer` |
| Holdout | `--factory L`（不建序列面板） | `--factory T`（序列+因子） |
| 落盘 | `live/yhat_l/` | `live/yhat_t/`（旧 `yhat_tf/` 迁此或别名） |
| 页内 Gate | 绝对指标（无 vs T） | 绝对指标（无 vs L）；跨厂对照留给枢纽 |
| 对照 | 不做页内硬闸相对臂 | 同上 |

**不变量**：一页只跑一臂；`hard_gate_vs_arm_L` 仅历史 LT 双臂跑次保留；新跑次不再写相对闸（或写 `gate=null`）。  
**旧 `/yhat-tf`**：302 → `/yhat-t`。命令面板入口含 Arm·L、Arm·T、Arm·R。

**Arm·R**（`/yhat-r`）与 Arm·L 同壳：全量因子、不建序列，求解器换成 Ridge。回归头拟合收益，排序头拟合日内稠密名次。落盘 `live/yhat_r/`，权重文件 `ridge.json`。

## 2. 为何这样拆

与 [design-spine](../design-spine.md) 一致：

- **已发生 → 估计 → 验证 → 动作**；执行套更换须人审。
- 回测与 live 各读自己的槽，打分实现同源。研究套服务历史回测，执行套服务 live。
- 工厂并行验证配方；枢纽只执行已经留下的配方，避免在同一页又搜索超参又换 live。

**现行错位（债）**

| | 现行 | 目标 |
|--|--|--|
| `/yhat-t` · `/yhat-l` | 成功跑次写入 `{版本号}.weights/`；离线回测不在本页，到 `/yhat-bt`；不写套槽 | 枢纽按配方例行执行后，历史回测仍只读研究套 |
| `/quant` | 在枢纽页直接拟合 LGB 四头，维护研究套 / 执行套并人审 promote | 选定工厂配方后例行写入研究套；执行套只从研究套晋级 |
| 版本库 | 工厂跑次是设置 + 指标 + 日志；`model_versions` 才是套槽文件 | 工厂制品含权重；套槽滚动产物仍只写在枢纽 |

## 3. 制品与评测契约（跨工厂）

### 3.1 统一制品（Conceptual Artifact）

每个可被枢纽引用的版本至少包含：

| 字段 | 含义 |
|--|--|
| `model_id` | 稳定 id（建议：后端 + head + fitted_at/run_id） |
| `head` | `oo` \| `tc` \| `oo_rank` \| `tc_rank`（API 勿与 suite 的 `tau` 混用时要有显式映射） |
| `backend` | `lgb` \| `transformer` \| `ridge`（可扩展） |
| `fit_params` | 配方里的超参与因子方案（结构、因子包、采样、lookback、Holdout 天数） |
| `fingerprints` | 特征包、universe、lookback、CS-z / 物化指纹 |
| `eval_report` | Holdout 指标、正式对照标记、评测宇宙。这是「配方值不值得执行」的证据 |
| `weights_ref` | 可加载权重路径。按版本号访问、加载、预估；离线历史回测、冒烟和枢纽执行都读它；**不等于**已进入研究套或执行套 |
| `live_eligible` | **仅**表示评测够格、可以被枢纽选为待执行配方；**不等于**已写入执行套 |

模型中心拉起的成功拟合会按版本号留下可加载权重。子进程在预测结束、权重仍在内存时，把文件写入 `{head}.weights.pending`（环境变量 `YHAT_FACTORY_RUN_ID` 对上当次 job）。`archive_factory_run` 核对 `run_id` 与 pid 后改名为 `versions/{head}/{版本号}.weights/`，并在版本 JSON 写入 `weights_ref`。对不上或跑次失败则丢掉临时目录，不挂到版本上。直接跑 Holdout 脚本、没有该环境变量时不写权重。

```text
versions/{head}/{版本号}.weights/
  meta.json     # 结构、序列 clip、因子列序、因子包、eval_start / eval_end
  state.pt      # Arm·T：CPU state_dict
  model.txt     # Arm·L：LightGBM save_model 文本
  ridge.json    # Arm·R：截距与系数
```

`meta.json` 带上版本档案里没有的打分伴随信息：`d_seq_in`、`d_factor`、网络结构、推理 dropout=0、训练时序列 1%/99% clip 上下界、因子列序与因子包。删除版本或超出保留条数时，该目录与 JSON、日志一起删除。`load_factory_weights(head, 版本号)` 只在版本 JSON 存在时读取。历史回测的四头读这个目录里已启用的版本；ŷ_τ30…90 仍读套槽。离线组合回测按版本号加载并预估（§3.4）。

### 3.2 跨工厂可比评测

同一 `head` 对齐：

- 同一 Holdout 交易日窗与评测宇宙（`eval_shared`）
- 同一标签与 CS-z 口径
- 相对基线规则可复用 Scheme LT 硬闸思想（见 [arm-t.md §8](arm-t.md)），升格为 **工厂间通用评测契约**，而非 TF 私有流程

探索跑（如 T 采样 10%、core 因子）可归档，但须打标；**正式对照**（full 因子 + 全样本 + 共享评测）才建议 `live_eligible`。

### 3.3 枢纽执行的两个槽

枢纽注册的是「研究套 / 执行套采用哪一套工厂配方」，不是把某一次工厂跑次的冻结权重永久钉死。每次例行执行产生该槽自己的新版本。ŷ_τ30…90 的回测和 live 读槽。四头 ŷ 的历史回测改读 `live/yhat_hub/arms.json` 里所选臂的工厂启用版本，回测页不再另挂工厂下拉。

| 槽 | 谁写入 | 谁读取 | 门禁 |
|--|--|--|--|
| **研究套** | 枢纽按已选定配方例行调用工厂训练实现 | ŷ_τ30…90 的历史回测默认。四头 ŷ 改读该厂 `enabled.research` | 配方已有工厂评测。四头可以不同臂 |
| **执行套** | 只从研究套人审晋级。部分头晋级时全样本再拟合，门禁仍追溯研究套样本外 | live / 交易执行。回测表单可改选本槽做对照 | 人审；禁止随工厂拟合结束自动换权重；缺执行套不退回研究套 |

沿用现行读法（见 [quant.md](../quant.md)）：回测默认研究套，live 只读执行套。

执行时还要守住这些接缝，否则换后端之后 `rank_lots` 的含义会变：

1. **成套。** 入场看 `y_oo_fuse`（ŷ_oo 与 ŷ_τc），买序看两路 rank。四头的采样、因子包、评测窗口对不齐，不能进同一条研究套。
2. **分数尺度。** `y_*_rank_score` 是模型原始分，只用于买序（固定 0.6/0.4，不进配置）。名次门槛看当天 1..n，不看原始分。写入套槽之前要约定原始分还是当日截面 z，两种尺度不能混在同一次加权里。
3. **信息集。** Arm·T 的 τc 只有开盘锚。回测 `fill_clock` 在 09:35–10:00 会用分钟前缀重算 ŷ_τc 并重挂 τc_rank。开盘锚配方不能绑到这个时钟。
4. **日期。** 研究套在某日可被回测使用，仅限该版 `eval_start` 之后、且落地时间不晚于该日的样本。训练窗内的重打只说明加载成功。更长历史靠研究套按切日滚动，不靠一份权重覆盖全部过去。

### 3.4 离线历史回测（看收益）

Holdout OOS 之外，还要看这版模型的历史回测收益。每个成功版本因此必须同时满足三步：按版本号访问、加载权重与打分伴随信息、对指定交易日预估。回测中心只消费这份预估，用该页保存的 rank_lots 算出收益，报告记在 `live/yhat_bt/`。

历史回测页不另挂工厂版本下拉。四头 ŷ_oo / ŷ_τc / ŷ_oo_rank / ŷ_τc_rank 按 `live/yhat_hub/arms.json` 读取对应工厂的启用版本（研究套 `enabled.research`，执行套 `enabled.live`），用 `load_factory_weights` 打分。没有启用版本或没有 `weights_ref` 的头不打分。ŷ_τ30…90 仍读套槽。历史回测页的规则保存会同步到交易执行。

离线验证在回测中心 `/yhat-bt`：四头各选 Arm·R / Arm·L / Arm·T，再各选该臂一版带权重的配方，后台加载权重并预估，用本页自己的 rank_lots 算出收益。臂只决定本页看哪一家工厂的版本，不写 `arms.json`。同臂四头和跨厂组合都在这里，不在三家工厂页底。权重、入场、强档、y_*>0、形态闸和本金只写在 `live/yhat_bt/`，不回写历史回测，也不改 live。日分价闸和可调成交钟仍只在历史回测页。成交固定 09:30。它不调用历史回测页的跑回测入口，不写研究套、不写执行套。

`/yhat-bt` 只读三家工厂已经落盘的版本，四头可以来自不同后端。两条排序头后端相同时买序用原始分（main 组合：Arm·R 的 ŷ_oo / ŷ_τc，Arm·L 的 LambdaRank）；后端不同时买序改用当日名次。回归头保持预测收益。同样不进历史回测页，不写套槽，不改 live。

离线回测对观察池全池打分并成交（截面 z 与打分同一份池）。运行台展示累计收益、超额、最大回撤、决策收益、准确率、命中率和窗口，不展示换手。

一次计入收益的交易日，是四头评测窗的交集：从最晚的 `eval_start` 到最早的 `eval_end`。更早的日期即使用这套权重预估成功，也不算这几版的历史回测收益。要更长的收益曲线，按版本落地顺序拼接：每个交易日只用当时已经存在的版本预估。

调仓收益要成套分数：`y_oo_fuse` 来自 ŷ_oo 与 ŷ_τc，买序来自两路 rank。四头缺一不可。Arm·T 的 τc 是开盘锚，离线回测的 `fill_clock` 固定 09:30。

## 4. UI 目标形态

### 4.1 Transformer 工厂（现模型中心）

| 做 | 不做 |
|--|--|
| 四头拟合、双臂对照、Holdout 日志/console | 存草稿 → 晋级研究整套心智 |
| **跑次版本下拉**：选中只读回看该版参数、指标和日志；可删除该条归档 | 复用 `/quant` 的 `model_versions` suite API（schema 不对）；删除时改当前拟合或写 live |
| 工作配置（可隐式，无「存草稿」按钮）+ 每次成功/失败 ingest 归档 | 产物栏 / 检查栏 / 摘要栏（信息迁入 console + 版本 meta） |
| 版本徽章：过闸 / 正式对照 / 采样% / failed | promote-live、写 active |

**交互不变量**

1. 选历史版 = **只读回看**；改参再拟合 = **新版本**（不覆盖旧档）。删除去掉该条归档、日志副本和 `{版本号}.weights/`，不改磁盘上的 last / job。已删掉的失败不再当作上次拟合显示；列表里还有版本时，概览改看剩下的最新一条。
2. 拟合进行中：console **优先当前 job**，不被历史选中版盖住。
3. 启用某一版只改该厂的 `enabled` 指针。枢纽和模型中心都能点，不写套槽模型文件。

### 4.2 LightGBM 工厂（规划页）

与 TF 工厂同壳不同后端：验证配方、评测、版本。超参网格从 `/quant` 迁到本页。跑次落在 `live/yhat_l/`。启用写在本厂版本的 `enabled` 指针上，枢纽和本页都能点，不写套槽模型文件。

### 4.3 研究枢纽

分区建议：

1. **数据准备** — 日线 / 分钟 / L1·L2 物化（工厂只声明依赖指纹）
2. **配方选用与执行** — 四头各自选 Arm·R / Arm·L / Arm·T，例行拟合调用该厂训练，启用写在该厂版本上。页上现有滚动验证（`roll-gate`）不写模型，不能代替拟合。
3. **探针 / 日报 / 分档** — 保持现有运维能力

枢纽页不再做配方搜索。例行拟合只重复已选定的配方，并调用工厂的训练实现。

四头拟合卡复用工厂运行条（`.yhat-tf-run`）。臂在概览卡的下拉里选，概览不再挂配方带。参数写在这一头的卡上，跟所选工厂同一套。拟合和版本都落在该厂，不写套槽版本。

| 套配方 | 卡上参数组 | 卡体 |
|--|--|--|
| LightGBM / LambdaRank | 数据：Holdout、训练窗。ŷ_τc / ŷ_τc_rank 另有前缀 | 因子表 |
| Ridge | 数据，另加 λ | 系数表 |
| Arm·T | 实验、数据、训练、模型与工厂同一套，可改。loss 按头固定（回归头 smooth_l1，排序头 lambdarank） | 运行台：Rank IC、ICIR、命中、Top10% y。无因子表 |

ŷ_τc 在枢纽的 id 是 `tau`，工厂是 `tc`，卡上做这一层映射。ŷ_τ30…90 和回测中心不进这张卡。当前页 `data-quant-recipe="transformer"`。四头各自从 Arm·R / Arm·L / Arm·T 里三选一，选择落在 `live/yhat_hub/arms.json`，缺省全是 T。卡上没有「研究 | 执行」切换，也不铺研究浅蓝。按钮是「拟合研究」「拟合执行」，调用所选工厂的 `start_holdout_fit`。Arm·T 参数与工厂一致（采样 10%、oo 用 core、τc 用 full、Holdout 60、窗 oo / τc / τc_rank 900、oo_rank 700、池子 800）。Arm·L / Arm·R 用该厂默认窗长（oo 600、τc 120、两条排序头 700、Holdout 20），池子是大池或沪深300，Arm·R 另有 λ。换臂时，训练窗和 Holdout 仍等于上一臂默认值的才改成新臂默认，改过的数字保留。指标从该厂状态画到运行台。每头一个版本框，列表是该臂跑次（`/api/quant/yhat-r|l|t/versions`），可预览、可删除。历史回测按头读取对应工厂里已启用、且带权重的版本。

## 5. 阶段落地（A → D）

### 阶段 A — 工厂收口（优先）

**目标**：双页工厂独立拟合/评测，仍 `live_allowed=False`；再上版本管理。

## 7. 风险与约束

1. **枢纽膨胀** — 套槽执行 + 分档已够重；禁止再把配方搜索塞回枢纽页。
2. **组合爆炸** — 四头 × 两后端；研究套默认整套同一后端、同一配方。
3. **评测不可比** — 无统一 Holdout 契约则枢纽无法判断哪套配方值得执行。
4. **两套 LightGBM** — 迁移完成前，`/quant` 仍直接拟合进套槽，`/yhat-l` 的跑次不进套槽。回测读的是套槽，不是工厂档案。
5. **命名** — 对外称「工厂验证配方、枢纽执行配方」，避免把模型中心当成 live 控制台。
6. **物化** — 属数据平面，归属数据中心。Arm·L / Arm·R / Arm·T 四头读日线物化（oo 222、开盘 τc 218），不读分钟 322 列。截面 z 缺 open 立方则 `materialize_required`。单票 L1 未命中只在内存重算，不写湖。
7. **head 命名** — suite 历史 `tau` vs desk `tc`；套槽与 API 层做映射表，禁止静默混用。
8. **静态钉死** — 只登记一版工厂权重、让回测和 live 一直读它，满足不了套槽滚动，也满足不了「历史日只用该日之前的研究套」。
